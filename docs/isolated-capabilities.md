# Restricted Isolated capability profile

This is the sole supported Isolated execution design. Fresh unsaved intent targets Dangerous with mandatory fresh exact Save confirmation; explicitly selecting Isolated targets Main/Additional and also requires Save. Existing saved Isolated choices stay unchanged. Every executable Isolated capture must have `restricted-native-1` on every role and active policy. Versionless/v2 or v3-without-policy captures are archive-only and fail before dispatch, never gain permissions or use an older ambient HOME/environment path. No stored choices/history are converted. Docker and Dangerous remain separate. [Exact Fable handoff and upgrade consequences](../API_CONTRACT.md) govern the sequential UI, not installation.

## Actual boundary

Isolated is application/native-tool restriction, **not OS/process containment**. Every Additional entry runs sequentially with its own captured native policy; Main independently reviews and synthesizes their evidence into one draft. Main never acquires permissions from reviewer output. Questions invoke only captured Main. The existing validator, proposal/manual-edit protection, exact preview, submission confirmation, cancellation and immutable entry evidence are unchanged.

`HostExecutor` passes only the captured approved inventory to Claude/Codex's app MCP or the app-owned Pi adapter. `localTools` checks its private request capability and exact operation at invocation, validates read arguments, resolves real paths within checkout/resources, and rejects shell/write/publish/unknown operations even when a caller knows their names. It cannot read the disposable authentication home. Business calls pass through `ReadProviders` and `ReadOnlyMcpGateway`: exact profile/source/server/protocol/schema checks, explicit tool grants and resource ids, fixed destinations/methods, bounded responses and cancellation. No reviewer receives the native MCP endpoint/header or an unrestricted proxy. Loading inventory does not authorize calls.

Native controls complement this boundary:

- Claude: restricted mode, empty setting sources, `disableAllHooks`, disabled slash-command activation, no general built-ins, strict app MCP and exact allowed tools. A disposable HOME/config directory contains no inherited plugins/settings. API-key runs additionally use bare mode. Subscription runs deliberately do **not** use bare mode: canonical native docs say bare mode skips OAuth; their access token is supplied through the documented `CLAUDE_CODE_OAUTH_TOKEN` environment mechanism instead.
- Codex: disposable HOME/CODEX_HOME, ignore user configuration/rules, ephemeral/read-only/never-approval mode; shell/unified execution, shell snapshots, hooks, apps, multi-agent and skill dependency installation disabled. Shell-profile inheritance and image reading are disabled, and credential storage is explicitly file-based. Selected ordinary preferences are explicit CLI config, not an ambient config projection.
- Pi: disposable HOME/agent directory, explicit openai-codex provider/model, no project trust, offline startup, no discovered extensions/skills/templates/themes/context, exact tool allowlist. Only the app-owned adapter is loaded as code. Frozen trusted skills are supplied with native repeatable `--skill`; packages remain empty. Offline does not disable inference or provide network containment.

Installed executable customizations are deliberately **overridden**, not reasons to uninstall them or select Dangerous. A selected review that requires non-orchestration shell/hooks/plugins still fails actionably. Required disabled native skill activation is diagnosed; the app never executes interpolation, hooks, subagents or scripts on behalf of a skill. Static script resources may be read but do not grant an execution tool.

### Residual trust and limitations

The application, native binaries, executable search PATH and host/operator are trusted. Native helpers, managed/admin policy, OS keychain APIs, host-user privileges and native networking are not contained by tool allowlists or a replacement HOME. Claude structured-output helpers and Codex tool composition are not evidence of unrestricted shell access, nor is the app gateway an attestation of every future native helper. Managed native policy may override/reject CLI choices; this profile is not verified for a machine requiring managed executable startup behavior. Use separately supported Docker containment when that matters; no automatic fallback occurs.

The app starts from its own directory, never the PR checkout. It does not discover PR/project executable configuration. Source preparation remains the existing trusted Git/GitHub operation, outside the reviewer environment projection. Cancellation stops owned process groups, not adversarial detached descendants. None of these restrictions constrain explicitly consented Dangerous native tools or promise remote server honesty. A known read protocol still trusts the server implementation not to mutate while serving it.

## Trusted skills, not just the review entry

Save inspects known trusted native roots in addition to the independently selected review directory:

- Claude: selected native config root's `skills` directory.
- Codex: selected CODEX_HOME's `skills`, `~/.agents/skills`, and absolute operator `skills.config` paths; explicit disabled directories are excluded.
- Pi: selected agent root's `skills`, `~/.agents/skills`, and ordinary local paths from global `settings.json.skills` (relative to that config root, absolute or `~/`). An explicitly listed static directory inside a disabled plugin/package is eligible without loading that plugin.

No admin/system/project root, plugin/package registry, symlink tree or installer is crawled. Npm/git package specs and Pi glob/exclusion expressions are not resolved. Missing descriptions are not treated as discoverable skills. Native entry names/frontmatter and UTF-8 relative resources are retained in `SkillSnapshot`, with source identity and hashes, under per-source library directories. Limits: 2,000 inspected entries, 100 skills and 2 MB captured library JSON. Nonportable, binary, symlink, escaping or oversized resources are diagnosed rather than copied. Operator skill/instruction material must be trusted and secret-free, as with the existing selected-entry snapshot.

Pi uses native metadata discovery/on-demand loading from explicit frozen skill paths; the prompt directs it to `read_source` because unrestricted native `read`/`bash` are unavailable. Claude/Codex expose a **static read catalog**, preserving native names/descriptions/files but not native Skill/slash activation, interpolation, `$ARGUMENTS` expansion, hooks, forked agents or Codex executable dependency installation. These combinations are unsupported, not native parity. No generic skill execution engine is added. `hooks`, `context: fork`, `agent` and shell-interpolation activation entries are excluded with diagnostics. Dependency detection is best effort, not a proof that arbitrary prose has no requirements.

Libraries and ordinary instructions/preferences are frozen on Save, then copied to each run/revision/thread. Source edits do not modify queued captures; re-save to adopt them. Between sequential roles, library materialization is replaced, not unioned. The selected review entry and its own relative resources remain independent. Focused questions may consult the trusted library but never invoke the full review entry.

## Native authentication and configuration

No second credential vault or shared cross-harness login exists. Save stores only typed source references and local provenance. File existence is local evidence, not authentication success; the keychain is not probed. GET/SSE reads only cached state. At execution:

| Harness | Supported own authentication                                                                                                                                                    | Projection and limits                                                                                                                                                                                                                                                                                                    |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Claude  | Existing `ANTHROPIC_API_KEY`, then `CLAUDE_CODE_OAUTH_TOKEN` (native noninteractive precedence); otherwise default macOS `Claude Code-credentials` subscription keychain record | Only the selected model credential enters its process environment. Keychain access reuses the existing validator and rejects expiry within five minutes. No refresh token copied. Custom config-root keychain service naming, proxy `ANTHROPIC_AUTH_TOKEN`, Bedrock/Vertex/Foundry and custom endpoints are unsupported. |
| Codex   | Native file-based ChatGPT login or literal `OPENAI_API_KEY` in selected CODEX_HOME/auth.json                                                                                    | Only model access/id/account fields or API key copied to a mode-0600 disposable auth file. ChatGPT expiry within five minutes fails. Refresh is blank. Keyring/auto stores and custom model providers/endpoints are unsupported. Ambient OpenAI keys are not substituted for a missing file login.                       |
| Pi      | Its own selected agent auth.json `openai-codex` OAuth entry                                                                                                                     | Existing access/account/expiry validator; no refresh token, unrelated provider entries, key commands, models.json or executable auth helpers projected. Other providers are unsupported, even if installed.                                                                                                              |

Reviewers no longer receive the application's ambient environment under this policy. Operational baseline is PATH, fixed LANG, disposable HOME/TMPDIR/XDG locations, harness-specific disposable config location and explicit startup controls. Local app gateway capability variables are added separately. MCP/business credentials remain in the host connection closure. No NODE_OPTIONS, shell startup variables, GitHub/business tokens, proxy credentials or another harness's model credentials are spread into reviewers.

Supported native model/low-medium-high effort/global instruction text remain captured. Claude language, Codex personality and Pi transport preferences are selectively projected; selected models/profile controls override inherited permissions and executable customizations. Other fields are reported as unsupported or deliberately overridden rather than copied wholesale. Unsupported provider/store combinations fail with useful diagnostics, not a different harness's credentials.

The app never initiates login or refresh and never writes source auth/config stores. Native subscription access remains possible through these existing mechanisms, not a live-availability promise. Disposable native files can still be modified by native login/cache code; expired mid-session Codex/Pi clients might attempt a failing refresh without a usable refresh credential. No OS network rule prevents such native attempts. Source stores remain outside projected homes. Long-session auth behavior and native managed/login effects have not been newly exercised against actual native binaries. Literal model-secret output and activity are rejected/redacted; provider results containing the selected credential literal are rejected. This is not an information-flow proof against arbitrary encodings or malicious native executables.

## Native MCP reuse and exact support

See [known profiles and contribution contract](known-mcp-profiles.md) and [exact Fable endpoints](../API_CONTRACT.md#isolated-capability-policy-exact-fable-handoff).

Explicit discovery parses Claude `mcpServers` JSON or Codex `mcp_servers` TOML. Parsing a file with inline headers necessarily sees those configuration bytes, but does not resolve a separate credential store, authenticate, execute commands, start a server or retain header values. The normal supported path is discover, choose connection/profile/resource scope, explicitly Load tools, explicitly choose enable/tool permission. No raw manifest authoring is needed for the supported native stateless document profile. Existing GitHub/Linear/Notion audited host-provider manifests remain supported and become available to explicitly captured v3 Isolated policies; this does not claim compatibility with those providers' arbitrary native MCP/OAuth servers.

Supported native transport is stateless JSON HTTPS with a literal `Authorization: Bearer ...` header, public IPv4/TLS/port 443, exact `/mcp`, fixed protocol and one exact document tool/schema. Claude `type:"http"` and Codex `http_headers` forms are supported. All other source keys/auth shapes are diagnosed unsupported. Local stdio **never runs**: discovery, import, a permission checkbox, Load and Test cannot grant host-code trust. Use an independently supported Docker workflow or explicit Dangerous native execution where appropriate; neither is activated by this feature. Pi has no core native MCP format, so executable extension-specific formats are unsupported, but Pi reviewers can use approved app-gateway reads imported from a supported source.

The source reference pins routing/auth form/native enable/tool restrictions, profile bytes and exact resource ids without credential values. Credential rotation at the same bounded reference is resolved at execution, not stored. Endpoint/profile/source restriction drift fails before forwarding; actual server/schema drift fails inventory validation. Manifest-based historical references still pin complete manifest bytes. All new discoveries/re-imports/Load actions leave enabled false and tool grants empty, including an unchanged reload. Unknown tools or readOnlyHint never grant access. Multiple enabled connections exporting the same tool name fail as ambiguous, not first-wins routing.

Load inventory is persisted local/synthetic/live-inventory evidence with `connected:false`. Test is separate, performs the bounded first-resource read and grants nothing. Only `scope:"live_read"` **and** `connected:true` mean a successful point-in-time live read. Tests are cached in memory and absent after restart; inventory and policy survive restart but never mean connected or containment-verified. Existing captured grants survive Settings changes by design; settings edits are not retroactive revocation. Source/schema drift and cancellation still fail captured calls closed.
