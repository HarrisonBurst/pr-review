# Host-owned Axiom review reads

## Supported route and public evidence

`axiom-mcp/1` uses the existing `McpOAuth`, macOS Keychain interface, guarded SDK Streamable HTTP transport, `ReadProviders`, `ReadOnlyMcpGateway` and `WorkflowBroker`. No separate credential framework, copied native login, executable plugin, REST fallback or Docker credential mount is introduced.

Official public sources:

- [Axiom MCP setup](https://axiom.co/docs/console/intelligence/mcp-server) recommends browser OAuth at `https://mcp.axiom.co/mcp`. It also documents personal access token plus `x-axiom-org-id` headers as an alternative. This implementation chooses the recommended OAuth route, not that alternative. Account/organization choice belongs in Axiom sign-in. The hosted MCP routes results through US infrastructure; queries can incur cost. [Role query-cost limits](https://axiom.co/docs/console/intelligence/query-cost-limits) are a provider setting, never changed by this app.
- [Path-specific resource metadata](https://mcp.axiom.co/.well-known/oauth-protected-resource/mcp) declares exactly resource `https://mcp.axiom.co/mcp`, issuer `https://authorization.axiom.co`, header bearer support and no `scopes_supported`. The root resource metadata has a different audience and is not substituted.
- [Issuer metadata](https://authorization.axiom.co/.well-known/oauth-authorization-server) advertises S256, authorization code and refresh, `none`/basic/post client methods, `/oauth2/register`, `/oauth2/authorize`, `/oauth2/token` and `openid`, `offline_access`, `profile`, `email`. These are authentication scopes, **not a read-only Axiom permission**. No registration, authorization, refresh or token request was made during research. Client-ID metadata documents and device grants are advertised but not used. Revocation was not advertised; local Disconnect and provider-side session revocation remain distinct.
- [Official tools reference](https://axiom.co/docs/console/intelligence/mcp-server/tools) classifies `listDatasets`, `getDatasetFields` and `queryDataset` as reads, and dataset/dashboard/monitor/notifier changes and `sendFeedback` as writes. The [public server page](https://mcp.axiom.co/) supplies current descriptions including `datasetName`, `startTime`/`endTime`, observed field semantics, provider query limits and organization overrides. Its descriptions are evidence, not reviewer instructions or authorization.

The documentation does not publish complete current JSON input schemas. The former official `axiomhq/axiom-mcp` repository is deprecated and its old `queryApl` tool is not this hosted contract. Direct public access to `axiomhq/mcp` source returned 404; search-indexed issue45 references APL plus `datasets` but is not current schema proof. The generated `apl`/`datasets`/`startTime`/`endTime` request is an explicitly limited adapter contract, validated against the loaded/current provider schema before dispatch. The inert provider tests exercise that contract, not authenticated live compatibility. A provider schema requiring another shape fails closed rather than guessing another argument or widening the request. No live tools/list or content operation was performed.

## Authentication and guided setup

The existing Connections modal is the only necessary setup path. With Isolated or Docker selected, discover the trusted native definition and click **Connect**:

1. Import the matching profile and discover public requirements automatically. The Axiom-only scope rule allows an omitted resource scope list only when the issuer explicitly advertises the requested scope. An explicitly empty/restrictive resource list, missing issuer scopes or changed issuer/resource/destination does not authorize a fallback. Other profiles retain their rules.
2. The dialog offers public-client registration with the existing typed **Register a new MCP OAuth client** consent. An eligible existing client remains an option. There is no required Axiom token or client secret for the public route; if a confidential client is chosen, its secret uses the existing local write-only password field and host store. Nothing is registered automatically.
3. Complete Axiom account/organization sign-in in the same browser. The dialog explains that `openid offline_access` supports sign-in/renewal, that the host credential can carry the user's write capabilities, and that the broker still permits only approved reads. No independent identity/workspace verification prerequisite is added.
4. Exact or omitted requested scopes authenticate under the existing policy. Extra returned capabilities require the complete original-browser local disclosure and unchecked exact consent; missing requested capabilities cannot be overridden. Refuse, Close, cancellation, expiry and restart never accept extras. Scope decoding uses case-sensitive space-delimited RFC tokens, not Slack comma normalization. Renewal cannot widen accepted capabilities or replay an ambiguous rotation.
5. Load tools and select reads, initially all unchecked. The guided path loads once automatically when it remains open; a returned disclosure resumes via **Load read tools**, preserving the existing return semantics. Unknown and write definitions may be visible under Advanced inventory but are never grantable.

**Connected** means admitted app-owned authentication (synthetic fixtures are labeled). The card separately reports not-set-up/disabled/granted review access and missing execution setup. No Test, discovery or inventory result manufactures live readiness. **Test connection** requires enabled explicit `listDatasets` permission and performs exactly `listDatasets({})`, no event query, with the normal guarded host refresh if needed. Missing grants contact nothing. Only a successful actual transport returns `live_read`/`connected:true` as point-in-time read evidence; inert success is `synthetic_transport`/false. Tests verify neither independent identity nor dataset isolation/completeness.

## Read bounds

- `listDatasets({})`: one provider dataset listing, no arguments, organization override, pagination or linked-resource fetch. The existing transport/result bounds apply; this is not a promise of complete inventory or a provider-side row limit.
- `getDatasetFields({datasetName})`: one events/traces dataset's observed fields. Dataset names are 1-80 ASCII alphanumeric/dot/underscore/hyphen characters, beginning and ending alphanumeric. No metadata expansion or organization override.
- `queryDataset({datasetName,startTime,endTime,filterField?,filterValue?,limit?})`: an app-authored narrower reviewer schema, not arbitrary APL passthrough. Both UTC timestamps are required, calendar-valid, ordered and at most one hour apart. `limit` is1-20, default20. Optional exact string equality requires both a bounded field identifier and a value of at most500 characters. The host generates one quoted dataset, an optional safely quoted equality filter and `take N`, then sends `apl`, the singleton `datasets` list and exact time bounds. No raw query, union, cross-dataset lookup, caller URL, organization override or control statement is accepted. This supplies bounded event samples, not general analytics, metrics support, deterministic ordering or a scan-cost guarantee.

All other tools are denied regardless of naming, profile prose or `readOnlyHint`. Invalid arguments and forged grants fail before credential/provider access at both gateway and direct credential entry. Fresh current schema validation precedes tools/call; immutable source, profile, OAuth generation/client/issuer/resource and schema fences remain. Load clears grants even when unchanged. Text/structured results remain untrusted, bounded to200KB and15seconds with no automatic continuation. Credential/private capability echoes reject the whole result. Axiom's four public authentication scope literals are not substring canaries; private extra identifiers remain protected and no accepted scope list is exported to reviewers.

Isolated and Docker share the host credential closure. The new read schema enters the existing broker policy digest, so older Docker artifacts need the normal explicit recapture/setup when they no longer match. Existing captures, user data, settings and Dangerous native sessions are not migrated, reset or reauthorized. This artifact performs no setup or installation.
