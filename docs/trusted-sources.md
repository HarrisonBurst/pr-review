# Trusted source capture

Select a trusted absolute Markdown review entry in Settings. The skill is not bundled. Save freezes its entry and bounded resources; changed bytes or source identity need explicit re-save. The app never edits installed skills or native configuration.

The selected entry may use a bounded file symlink chain, including Nix/Home Manager indirection. Its logical filename and companion directory are retained; the terminal file's parent is not enumerated. Selecting a terminal entry directly in the Nix store is refused. Exact selected-entry backup siblings are excluded; required dependencies cannot be silently discarded. Cycles, dangling links, credential-store paths and unsupported resources fail closed.

Docker additionally supports bounded declared native/Nix library links and source-bound optional external skill leaves. A leaf's metadata disclosure and unchecked per-alias read selection are separate from executable-code approval and host-effects consent. Unselected optional direct external skill directories are omitted before reading their contents. Selected entries, external files, nested escapes and parent-root links are not made optional.

Only Docker skill `assets/` companions may include recognized non-executable WOFF2/PNG bytes. Encoding, media type, decoded size and exact digest are disclosed. Header/envelope recognition is not full image/font validation or rendering proof. Other modes, local MCP and explicitly selected external leaves remain UTF-8-only. Docker retains 2 MB per-file, 8 MB decoded aggregate and 16 MB serialized resource bounds; general capture and each external leaf retain their independent 2 MB bounds.

Source-bound Docker exclusions are narrow, explicit and content-bound: recognized Herdr SessionStart/status-line items, the exact singleton official Slack activation flag and the recognized Google Workspace skill layout. They affect the frozen Docker projection only. No automatic omission, native-file mutation, plugin enablement, business read grant or blanket future approval follows. Changed source bytes, links or layout require new inspection and approval.

See [the exact source/exclusion contracts](../API_CONTRACT.md#source-bound-docker-exclusions-and-handling) and [execution boundaries](../EXECUTION_BOUNDARY.md) for roots, limits and immutable capture semantics. Imported portable files do not prove arbitrary native features work.
